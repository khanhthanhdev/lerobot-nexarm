Calibrate the simulator to your follower arm

This measures which way each real joint turns and where its zero sits, so the MuJoCo twin poses the same raw servo values the same way your arm does. You only need the follower arm and about ten minutes.

You need
Follower on USB, power on, the Hiwonder desktop app
Time
About 10 minutes
Result
outputs/nexarm/joint_mapping_probe.json

  1. Prepare the arm

    1. Power the follower and connect it by USB.
    2. In the Hiwonder desktop app, run Home. Every servo goes to raw 2048: the upper arm stands vertical, the elbow bends 90°, and the forearm and gripper point straight out over the table, gripper half open. This gives you a known starting pose.
    3. Close the desktop app completely. It holds the serial port, and the probe cannot connect while it is open.
    4. Clear the space around the arm. You will move it by hand.

    If you are not sure which port the follower is on, run this and unplug the arm when it asks:

    uv run lerobot-find-port

    The follower is usually /dev/ttyUSB1 on Linux, or a COM port on Windows.

  2. Start the probe

    Run it from the repository root:

    uv run python examples/nexarm/probe_joint_mapping.py --port /dev/ttyUSB1
    Hold the arm before the first Enter. The first prompt switches the motors off. Without support, the arm drops under its own weight.

  3. Answer the prompts

    The probe uses one reference pose: the arm straight up, which is not the app's Home pose. From Home, you get there by raising the forearm 90° until it points at the ceiling; the upper arm is already vertical.

    From there you turn one joint a quarter turn (90°), answer a question, and return to straight up. Directions are always from the robot's point of view: front is toward the work area, left and right are the robot's own left and right.

    Motors turn off
    Support the arm with one hand, press Enter.
    Pose straight up
    Arm facing the work area; upper arm, forearm and gripper all vertical, gripper pointing up. Hold it still, press Enter.
    Wrist camera side
    Which side of the gripper is the wrist camera on? Type f b l or r.
    shoulder_pan
    Turn only the base a quarter turn counter-clockwise, seen from above. Then return to straight up.
    shoulder_lift
    Tilt only the shoulder until the upper arm is horizontal, either way. Say where the upper arm points (f/b/l/r). Return to straight up.
    elbow_flex
    Bend only the elbow until the forearm is horizontal, either way. Say where the forearm points. Return to straight up.
    wrist_flex
    Bend only the wrist until the gripper is horizontal, either way. Say where the gripper points. Return to straight up.
    wrist_roll
    Turn only the wrist a quarter turn counter-clockwise, seen from above. Return to straight up.
    Your Home pose does not matter. The probe reads the raw values in the straight-up pose instead of assuming they are 2048. It works whether Home is upright or bent.

  4. Check the result

    The probe prints one line per joint and saves the file. The offsets below are what your arm should give, predicted from the Home pose in the photo of your follower. Your measured offsets should land within a few degrees; signs and tick counts depend on the arm, so treat those as layout only.

    qpos = sign * (raw - 2048) * 2*pi/4096 + offset_rad
shoulder_pan   sign +1  offset    +0.00 deg  quarter turn 1021 ticks
shoulder_lift  sign -1  offset   -35.70 deg  quarter turn 1030 ticks
elbow_flex     sign +1  offset   -60.70 deg  quarter turn 1018 ticks
wrist_flex     sign -1  offset   +24.80 deg  quarter turn 1026 ticks
wrist_roll     sign +1  offset    +0.00 deg  quarter turn 1024 ticks
    • sign is +1 when the real joint turns the same way as the sim joint, −1 when it is reversed.
    • offset is the sim angle at raw 2048, so it describes your Home pose. If one is off by about 90° from the values above, that joint's quarter turn or direction answer was wrong: run the probe again. wrist_roll can read 0° or ±90° depending on which side the wrist camera is on.
    • quarter turn should be close to 1024 ticks (a quarter of 4096). Anything outside 768–1280 prints a warning.

    Read every line that starts with WARNING:. If one appears, see Troubleshooting below and run the probe again.

  5. Use the mapping

    Pass the file anywhere sim data is made. Datasets and calibrations remember which mapping they used and refuse to mix with a different one.

    MUJOCO_GL=egl uv run python examples/nexarm/generate_sim_dataset.py \
  --repo-id=local/nexarm_sim_pick_place \
  --root=outputs/datasets/nexarm_sim_pick_place \
  --episodes=20 \
  --joint-mapping outputs/nexarm/joint_mapping_probe.json
    WhereOption
    generate_sim_dataset.py--joint-mapping PATH
    generate_stack_bowls_dataset.py--joint-mapping PATH
    calibrate_sim.py--joint-mapping PATH
    lerobot-* with nexarm_sim--robot.joint_mapping_path=PATH
    lerobot-train / eval with the nexarm env--env.joint_mapping_path=PATH

    To check by eye: pose the real arm, note its raw values, set the same values with the sliders in examples/nexarm/simulate.py, and compare the two poses.

Troubleshooting

MessageWhat to do
Port busy, or no reply from the armClose the Hiwonder desktop app and any other script using the follower, then check the port with lerobot-find-port.
<joint> moved only N ticks; redo its quarter turnThat joint barely moved. Run the probe again and turn the joint a full quarter turn.
a quarter turn read N ticks, 1.4x the expected 1024The move was not close to 90°. Redo it, judging horizontal and vertical against the table.
<joint> tilts left, but the sim joint only tilts front/back hereThe arm was not facing the work area in the straight-up pose. Face it front and run the probe again.
raw 2048 is at sim qpos … outside the joint rangeThe mapping is valid, but the sim joint limits need re-centring before you rely on that joint near its ends.
Sim arm stops short of the real oneKnown issue: the sim's joint limits are centred on the CAD pose, not on your Home pose. With your offsets the sim elbow can only rise about 74° from Home, and shoulder lift and wrist flex lose about 36° and 25° on one side. The joint limits in the sim model need re-centring on Home.

What still needs the leader arm

  • Leader vs follower alignment (calibrate_arms.py) compares the two arms. With the follower alone, check its zeros on the desktop app's Servo Advanced page instead.
  • Fitting the sim's motion (calibrate_sim.py) needs recordings with both commands and measured positions. Desktop-app recordings with the motors off only have positions, so they cannot be used.
  • You can still time each servo on the follower alone. This moves the arm under power, so clear the space first:
uv run python examples/nexarm/servo_step_test.py --port /dev/ttyUSB1 --joint elbow_flex --delta 600
